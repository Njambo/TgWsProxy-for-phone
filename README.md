# TG WS Proxy Mobile

Открытое Android-приложение (MIT) — локальный **MTProto-прокси** для Telegram,
который доставляет трафик через **WebSocket** к серверам Telegram.

```
Telegram (телефон) → 127.0.0.1:1443 → WebSocket/TLS → kwsN.web.telegram.org → DC
```

Прокси поднимается на самом телефоне, поэтому внешний сервер, VPN и чужие
прокси не нужны. Данные остаются зашифрованными штатным MTProto.

## Что умеет

- Поднимает локальный MTProto-прокси на `127.0.0.1` как foreground service.
- Сам разбирает обфусцированное MTProto-рукопожатие клиента, вытаскивает DC
  и переупаковывает поток в WebSocket-сообщения к `kws<DC>.web.telegram.org`.
- Свой Cloudflare Worker (`*.workers.dev`) как обходной маршрут: его адрес
  не попадает ни в одну блокировку общих доменов (см. ниже).
- Через свой Worker поток идёт байтовым туннелем без нарезки на MTProto-
  пакеты: меньше кадров и копий, фото и видео загружаются ровнее.
- Автоматический TCP-fallback на DC напрямую, если WebSocket недоступен.
- Генерирует секрет, показывает `tg://proxy`-ссылку — подключение в один тап.
- Журнал соединений прямо в приложении.
- Поддержка TalkBack: элементы подписаны для экранного диктора; в режиме «Авто»
  приложение само замечает включённый в системе TalkBack и голосом сообщает
  о запуске и остановке прокси и о смене канала (Меню → Настройки → «Режим для
  экранного диктора»).
- Диктор: Меню → Настройки → «Диктор». Режим TalkBack, выбор «TalkBack или голос
  приложения» для озвучки событий, свой голос, скорость и тон на системном
  синтезе речи, переходы в системные настройки TalkBack и синтеза речи.
- Обновления: Меню → Настройки → «Обновления». Проверка новой версии, окно «Обновить» со
  скачиванием и установкой, раскрывающийся блок «Что нового» с описаниями
  последних сборок (берутся из текста коммитов).
- Терминал: кнопка на главном экране. Показывает все IP-адреса, которые использует
  приложение (дата-центры Telegram, шлюз WebSocket, узлы Cloudflare), и позволяет
  добавить свои: шлюз Telegram или узел Cloudflare. Свои адреса участвуют в подборе
  маршрута наравне со встроенными и применяются при следующем запуске прокси.
- Автоматическое создание Worker: кнопка «Создать автоматически» под полем Worker.
  По API-токену Cloudflare (шаблон «Edit Cloudflare Workers») приложение само создаёт
  Worker в вашем аккаунте и записывает его адрес в поле. Токен уходит только в
  api.cloudflare.com и нигде не сохраняется.
- Меню (три полоски в правом верхнем углу): «Профиль» (имя и сведения о ваших настройках) и
  «Настройки».
- Вход через Google (необязательный): Меню → Профиль → «Войти через Google». Одно нажатие:
  системное окно «Продолжить как…», после чего имя, почта и фото появляются в профиле.
  Данные хранятся только на телефоне. Чтобы вход заработал в вашей сборке, нужны два клиента OAuth
  в Google Cloud Console (Android: имя пакета `org.tgwsproxy.mobile` и SHA-1 вашего ключа; Web) и
  Client ID веб-клиента в `android/app/src/main/res/values/auth.xml` (поле `google_web_client_id`).
- Движок прокси: Меню → Настройки → «Движок прокси». Можно выбрать наш движок на Kotlin или
  оригинальный TG WS Proxy 1.12.0 на встроенном Python (Chaquopy): пул соединений, HTTP/2
  для медиа через Cloudflare, автообновление списка доменов. Код оригинала лежит без
  изменений в `android/app/src/main/python/proxy`; чтобы обновить его, замените файлы
  этой папки файлами из `proxy/` новой версии.
- Резервная копия: Меню → Профиль → «Скопировать настройки» и «Вставить настройки».
  Переносит все настройки (порт, секрет, Worker, свои IP, тему и остальное) на другой телефон.
- Темы: Меню → Настройки → «Темы». Режим (авто, светлая, тёмная) и цветовая схема
  (стандартная, синяя, зелёная, оранжевая, розовая, AMOLED).
- Никакой телеметрии, рекламы и сторонних серверов. Единственный запрос помимо
  прокси: проверка новой версии в GitHub Releases этого репозитория и, если вы сами
  запустите автоматическое создание Worker, запросы к api.cloudflare.com; а при входе через Google, который вы включаете сами, запросы к сервисам Google.

## Сборка

Нужны JDK 17 и Android SDK 35.

```bash
cd android
gradle assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

В репозитории настроен GitHub Actions (`.github/workflows/android.yml`):
пуш в `main` или ручной запуск собирает debug-APK и кладёт его в артефакты.

Протокольную логику можно проверить без телефона:

```bash
python3 -m pip install cryptography
python3 tools/verify_crypto.py
```

Скрипт зеркалит крипто-ядро Kotlin и проверяет рукопожатие, генерацию
relay-init и перешифровку в обе стороны для всех трёх тегов транспорта.
Этот же шаг выполняется в CI перед сборкой.

## Готовая сборка

Debug-APK из этого дерева: `dist/tgws-mobile-0.6.0-debug.apk`
(`org.tgwsproxy.mobile`, minSdk 26, targetSdk 35, подпись — стандартный
Android debug-ключ). При установке Android попросит разрешить установку из
неизвестного источника — для debug-сборки это ожидаемо.

Собрано на arm64-хосте без Android Studio: JDK 17 Temurin, Android SDK 35,
Gradle 8.9 в `~/.local/android-build`, а x86-64 `aapt2` из build-tools
запускается через `qemu-user` (обёртка `~/.local/android-build/aapt2-bin/aapt2`).
Контейнеру выделено 2 ГБ, поэтому heap Gradle урезан:

```bash
export ANDROID_HOME=~/.local/android-build/sdk
gradle assembleDebug --no-daemon --max-workers=1 \
  -Dorg.gradle.jvmargs="-Xmx900m -XX:MaxMetaspaceSize=512m" \
  -Pkotlin.compiler.execution.strategy=in-process \
  -Pandroid.aapt2FromMavenOverride=~/.local/android-build/aapt2-bin/aapt2
```

## Установка и использование

1. Установить APK на телефон.
2. Открыть приложение, нажать **Запустить**.
3. Нажать **Подключить Telegram** и подтвердить прокси в Telegram.
4. Приложение можно свернуть — сервис продолжает работать.

Ссылка для ручного подключения: Telegram → Настройки → Продвинутые → Тип
подключения → Прокси → MTProto, сервер `127.0.0.1`, порт из приложения,
секрет из приложения.

## Ограничения текущей версии

- Только Android (Kotlin). iOS — отдельный проект на Swift.
- Нет Fake TLS (`ee`-секрет) и relay-режимов — только прямой WebSocket и
  TCP-fallback.
- Нет пула/балансировки WebSocket-соединений: одно соединение на клиента.
- Код не собирался в контейнере разработки (там нет Android SDK): сборка
  выполняется в GitHub Actions, APK нужно проверить на устройстве.

## Дорожная карта

- Fake TLS-маскировка (`ee`-секрет).
- Пул WebSocket-соединений и переключение доменов при отказах.
- Настройки: собственный список DC/доменов, автозапуск при загрузке.
- Подпись release-APK и публикация в Releases через CI.
- iOS-клиент.

## Свой Cloudflare Worker

Shared-домены `*.co.uk`, на которых держится Cloudflare-маршрут, заблокированы
в РФ с 16.11.2026 — у такого трафика нет живого адреса. Свой Worker на
бесплатном `*.workers.dev` — это личный поддомен, которого в списках нет.

Worker бесплатный, а лимит 100 000 запросов в сутки у каждого свой, поэтому\
схема «у каждого пользователя свой Worker» работает без общих расходов\
и общего адреса, который можно заблокировать.

### Быстрый способ

[![Развернуть в Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/Njambo/TgWsProxy-for-phone/tree/main/docs)

Нажмите кнопку, войдите в Cloudflare (нужна только почта, карта не нужна),
подтвердите развёртывание и скопируйте адрес вида
`tgws-proxy.username.workers.dev`. Дальше сразу шаг 4 ниже.

### Вручную

Код Worker'а лежит в `docs/cloudflare-worker.js`. Развёртывание:

1. На [dash.cloudflare.com](https://dash.cloudflare.com/) → **Compute** →
   **Workers & Pages** → **Create application** → `Start with Hello World!` →
   **Deploy**. Подтвердить почту, если просят.
2. **Edit code**, заменить содержимое на `docs/cloudflare-worker.js`,
   снова **Deploy**.
3. Скопировать свой адрес с экрана — вида
   `random-symbols-1234.username.workers.dev`.
4. Вставить его в приложении в поле **«Свой Cloudflare Worker»** и нажать
   **Запустить** (или **Проверить связь** — проверка начнётся с Worker'а).

Несколько адресов можно указать через запятую. Маршрут ставится первым в
очереди; если Worker не отвечает, приложение пробует общие маршруты как
раньше. Бесплатный тариф Workers: 100 000 запросов в сутки, для прокси
этого с запасом. Worker принимает подключения только к адресам дата-центров
Telegram, поэтому чужие не смогут пустить через него посторонний трафик.
