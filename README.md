# TG WS Proxy Mobile

Открытое Android-приложение (MIT) — локальный **MTProto-прокси** для Telegram,
который доставляет трафик через **WebSocket** к серверам Telegram.

```
Telegram (телефон) → 127.0.0.1:1443 → WebSocket/TLS → kwsN.web.telegram.org → DC
```

Прокси поднимается на самом телефоне, поэтому внешний сервер, VPN и чужие
прокси не нужны. Данные остаются зашифрованными штатным MTProto.

## Что умеет

- Поднимает локальный MTProto-прокси на `127.0.0.1` как foreground service.
- Сам разбирает обфусцированное MTProto-рукопожатие клиента, вытаскивает DC
  и переупаковывает поток в WebSocket-сообщения к `kws<DC>.web.telegram.org`.
- Автоматический TCP-fallback на DC напрямую, если WebSocket недоступен.
- Генерирует секрет, показывает `tg://proxy`-ссылку — подключение в один тап.
- Журнал соединений прямо в приложении.
- Никакой телеметрии, рекламы и сторонних серверов.

## Сборка

Нужны JDK 17 и Android SDK 35.

```bash
cd android
gradle assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

В репозитории настроен GitHub Actions (`.github/workflows/android.yml`):
пуш в `main` или ручной запуск собирает debug-APK и кладёт его в артефакты.

Протокольную логику можно проверить без телефона:

```bash
python3 -m pip install cryptography
python3 tools/verify_crypto.py
```

Скрипт зеркалит крипто-ядро Kotlin и проверяет рукопожатие, генерацию
relay-init и перешифровку в обе стороны для всех трёх тегов транспорта.
Этот же шаг выполняется в CI перед сборкой.

## Установка и использование

1. Установить APK на телефон.
2. Открыть приложение, нажать **Запустить**.
3. Нажать **Подключить Telegram** и подтвердить прокси в Telegram.
4. Приложение можно свернуть — сервис продолжает работать.

Ссылка для ручного подключения: Telegram → Настройки → Продвинутые → Тип
подключения → Прокси → MTProto, сервер `127.0.0.1`, порт из приложения,
секрет из приложения.

## Ограничения текущей версии

- Только Android (Kotlin). iOS — отдельный проект на Swift.
- Нет Fake TLS (`ee`-секрет) и relay-режимов — только прямой WebSocket и
  TCP-fallback.
- Нет пула/балансировки WebSocket-соединений: одно соединение на клиента.
- Код не собирался в контейнере разработки (там нет Android SDK): сборка
  выполняется в GitHub Actions, APK нужно проверить на устройстве.

## Дорожная карта

## Протокол и благодарности

Здесь это независимая реализация на Kotlin, а не форк Python-кода.
